# האקווריום: מערכת ניהול לבית ספר לשחייה (צד לקוח)

אפליקציית React שבה מורות לשחייה והמזכירות שלהן מנהלות את העבודה היומיומית של בית הספר. במערכת רושמים תלמידות וקבוצות, מסמנים נוכחות בשיעורים ועוקבים אחרי תשלומים. היא גם מפיקה דוחות טיפולים בקובץ PDF, להגשה לקופות החולים ולחברות הביטוח.

המערכת נבנתה עבור לקוחה אמיתית, ופועלת בענן מול שרת ASP.NET Core 8 ובסיס נתונים PostgreSQL.

> המסמך כתוב בעברית, והמונחים הטכניים נשארו באנגלית.

---

## המטרה

בית ספר לשחייה מנהל הרבה פרטים קטנים: איזו תלמידה רשומה לאיזו קבוצה, כמה היא שילמה וכמה נשאר לה לשלם, מי הגיעה לכל שיעור, ומתי השיעור הבא. בנוסף, בסוף כל קורס צריך להגיש לקופת החולים דוח עם תאריכי הטיפולים, לפי טופס של הקופה.

לפני המערכת, כל זה נעשה במחברות, בטבלאות ובמילוי ידני של טפסים. המטרה הייתה מקום אחד, פשוט ונוח, שבו:
- מורה רואה בכניסה מה מחכה לה היום, ומסמנת נוכחות בכמה לחיצות, גם מהטלפון ליד הבריכה.
- מזכירה רושמת תלמידות, מעדכנת תשלומים ומפיקה דוחות, בלי לגשת לנתונים שלא שייכים למורה שלה.
- דוח לקופה נבנה מהנוכחות שכבר סומנה, ויוצא כקובץ PDF מוכן להגשה.

## משתמשים והרשאות

במערכת שני תפקידים: **מורה** ו**מזכירה**. כל מזכירה שייכת למורה אחת.

**כל מורה רואה רק את הנתונים שלה**, ומזכירה רואה רק את הנתונים של המורה שלה. הבידוד הזה נאכף בשרת, לכן גם בקשה ידנית לא תחזיר נתון של מורה אחרת. צד הלקוח מוסיף שכבה שנייה: הוא לא מציג למשתמשת קישורים, עמודים וכפתורים שאין לה הרשאה אליהם.

| יכולת | מורה | מזכירה |
|---|:---:|:---:|
| עמוד הבית: קיצורי דרך ותמונת מצב | ✓ | ✓ |
| תלמידות: רשימה עם חיפוש וסינון, הוספה, עריכה, כרטיס תלמידה | ✓ | ✓ |
| קבוצות: רשימה עם סינון, יצירה, עריכה, פרטי קבוצה ושיעורים | ✓ | ✓ |
| רישום תלמידה לקבוצה, ביטול רישום, עדכון תשלום | ✓ | ✓ |
| דוחות לקופות: יצירה, עריכה, תצוגה והורדה של PDF | ✓ | ✓ |
| החלפת הסיסמה של עצמה | ✓ | ✓ |
| עמוד הבית: השיעורים של היום | ✓ | |
| מערכת שעות לשבוע הקרוב | ✓ | |
| נוכחות: לפי שיעור, ובטבלה מלאה לכל הקורס | ✓ | |
| הזזה ומחיקה של שיעורים, ומחיקה של תלמידה או קבוצה | ✓ | |
| העברת תלמידה למורה אחרת | ✓ | |
| ניהול מזכירות: הוספה, סיסמה חדשה, ביטול גישה | ✓ | |
| הגדרות הדוח: חתימה ומחירי ברירת מחדל | ✓ | |

**איך ההרשאות ממומשות בצד הלקוח:**
- **`RequireAuth`** עוטף את כל העמודים חוץ מהכניסה. משתמשת שלא מחוברת מועברת לעמוד הכניסה, ואחרי ההתחברות היא חוזרת לעמוד שאליו ניסתה להגיע.
- **`RequireRole`** עוטף את העמודים של מורה בלבד. מזכירה שמגיעה לכתובת כזו, למשל דרך קישור ששמרה, רואה עמוד "אין הרשאה" ברור, ולא עמוד שבור.
- **התפריט נבנה ממקור אחד** (`navItems.ts`). כל פריט מסומן אם הוא למורה בלבד, ו־`navItemsFor(role)` מחזיר רק את מה שמותר לתפקיד. כך התפריט, הכותרת העליונה ועמוד הבית תמיד מסכימים ביניהם.
- **תוקף ההתחברות:** כשהשרת מחזיר `401` (פג תוקף, הסיסמה הוחלפה או שהגישה בוטלה), המשתמשת מנותקת, כל הנתונים שנשמרו בזיכרון נמחקים, ובעמוד הכניסה מופיעה הודעה "החיבור הסתיים, יש להתחבר מחדש".
- **אין הרשמה פתוחה.** זו מערכת פנימית של עסק. מורה נוספת על ידי מנהלת המערכת, ומזכירה נוספת על ידי המורה שלה, מתוך עמוד המזכירות.

## נוחות ושימוש ידידותי

המערכת נבנתה למורות ולמזכירות, לא לאנשי מחשבים. לכן הושקעה מחשבה בכל מקום שבו משתמשת עלולה להתבלבל, לחכות או לאבד עבודה.

**ברור מה קורה עכשיו:**
- כל עמוד שמציג נתונים מטפל בשלושה מצבים: טעינה (שלד אפור בצורת התוכן), שגיאה (הודעה וכפתור "לנסות שוב") ורשימה ריקה (הסבר וכפתור לפעולה הראשונה).
- כפתור ששולח בקשה מציג סימן טעינה, ולא מאפשר לחיצה כפולה.
- אחרי כל פעולה מופיעה הודעה קצרה בפינה, למשל "הנוכחות נשמרה" או "התשלום עודכן".
- השרת בענן "נרדם" כשאין בו שימוש. אם הכניסה לוקחת יותר מכמה שניות, מופיעה ההודעה "השרת מתעורר, זה יכול לקחת עד דקה", כדי שהמשתמשת לא תחשוב שהמערכת תקועה.

**הודעות שגיאה שאפשר להבין ולתקן:**
- כל שגיאה מהשרת מגיעה עם קוד, והלקוח מציג את ההודעה **ליד השדה הנכון**. למשל, אימייל שכבר קיים מסומן בשדה האימייל, ולא כהודעה כללית.
- כל הבדיקות של הטפסים (Zod) כתובות בעברית, ונבדקות עוד לפני השליחה לשרת: תעודת זהות, טלפון, אימייל, סכומים ותאריכים.
- המקרה הרגיש ביותר הוא שתי משתמשות שרושמות תלמידה למקום האחרון בקבוצה באותו רגע. השרת מחזיר `409`. הלקוח מציג ליד בחירת הקבוצה את ההודעה "המקום נתפס הרגע", ומרענן את נתוני הקבוצות כדי שהתפוסה המעודכנת תופיע מיד.

**לא מאבדים עבודה:**
- מי שמתחילה למלא טופס ומנסה לצאת ממנו, מקבלת שאלה אם לצאת בלי לשמור (`UnsavedChangesGuard`). כך זה עובד בטפסים של תלמידה, קבוצה, דוח והגדרות, ובעמודי הנוכחות.
- פעולה שאי אפשר לבטל, כמו מחיקה, ביטול רישום או ביטול גישה של מזכירה, מבקשת אישור עם הסבר ברור של המשמעות.

**חוסך לחיצות:**
- החיפוש והסינונים נשמרים בכתובת העמוד (`useUrlFilters`). אחרי כניסה לכרטיס של תלמידה, כפתור "חזרה" מחזיר לאותה רשימה מסוננת, ואפשר גם לשלוח קישור לרשימה מסוננת.
- החיפוש מחכה רגע עד שמסיימים להקליד (`useDebounce`), ולא שולח בקשה על כל אות.
- ערכים מתמלאים מראש: מחיר הקבוצה בטופס הרישום, והמחיר ומספר הטיפולים בדוח חדש (מתוך הגדרות המורה). כל ערך ניתן לשינוי, כי מורות נותנות הנחות לפי שיקול דעתן.
- בדוח לקופה, הכפתור "מילוי לפי הנוכחות" ממלא את תאריכי הטיפולים מתוך הנוכחות שכבר סומנה.
- עמוד הבית מותאם לתפקיד: קיצורי דרך לפעולות הנפוצות, מספרים חיים (תלמידות עם חוב, קבוצות פעילות, דוחות החודש), ולמורה גם רשימה של השיעורים של היום.

**נוח בכל מסך:**
- המערכת כולה בעברית ומימין לשמאל.
- בטלפון התפריט נפתח כמגירה, וכל טבלה מוצגת ככרטיסים שקל לקרוא ולגעת בהם.
- נגישות: כל שדה מחובר לתווית ולהודעת השגיאה שלו (`aria-describedby`), אפשר להגיע לכל רכיב במקלדת עם מסגרת מיקוד אחידה, ומי שביקשה במערכת ההפעלה פחות תנועה, לא מקבלת אנימציות.

## מבנה המערכת

### הקשר לשרת
```
דפדפן (React)  ──HTTPS + JWT──►  SwimSchool API (ASP.NET Core 8)  ──►  PostgreSQL
```
הלקוח לא שומר שום מידע עסקי בעצמו. כל הנתונים מגיעים מהשרת, דרך שכבת קריאות אחת.

### הטכנולוגיות
| תחום | בחירה | למה |
|---|---|---|
| בסיס | React 19, TypeScript, Vite | טיפוסים בכל הקוד, ובנייה מהירה |
| ניתוב | React Router 7 | נתיבים מקוננים, ושומרי הרשאה כרכיבים |
| נתונים מהשרת | TanStack Query | שמירה בזיכרון, רענון אחרי שינוי, ניסיון חוזר בתקלת רשת |
| מצב משותף | React Context | רק שני דברים משותפים באמת: המשתמשת המחוברת וההודעות הקופצות. לכן Redux מיותר |
| טפסים | React Hook Form עם Zod | ולידציה אחת שמגדירה גם את הטיפוסים |
| קריאות לשרת | Axios | Interceptors להוספת ה־Token ולתרגום שגיאות |
| טיפוסים מהשרת | openapi-typescript | הטיפוסים נוצרים מה־Swagger של השרת, כך שהלקוח והשרת לא נפרדים |
| עיצוב | Tailwind CSS 4 | כל הצבעים, הגופנים והפינות מוגדרים במקום אחד (`@theme` ב־`index.css`) |
| אייקונים | lucide-react | |
| איכות קוד | oxlint, jscpd | בדיקת קוד, ואיסור על שכפול קוד |

**כל רכיבי הממשק נכתבו בפרויקט עצמו**, בלי ספריית רכיבים מוכנה: כפתורים, שדות, חלונות (על `<dialog>` של הדפדפן), טבלאות, עימוד ושלדי טעינה.

### מבנה התיקיות
```
src/
├── api/              # שכבת הקריאות לשרת
│   ├── http.ts       # Axios: כתובת השרת, Token בכל בקשה, תרגום שגיאות
│   ├── apiError.ts   # מחלקת שגיאה אחידה וקודי השגיאה
│   ├── queryKeys.ts  # כל המפתחות של TanStack Query במקום אחד
│   ├── schema.d.ts   # טיפוסים שנוצרו אוטומטית מה־Swagger
│   └── <נושא>/       # students, groups, lessons, enrollments, attendance, reports, secretaries, auth, teachers
│       ├── api.ts    #   הקריאות עצמן
│       ├── hook.ts   #   useQuery / useMutation לכל קריאה
│       └── schema.ts #   סכמות Zod של הטפסים, והמרה מטופס לבקשה
├── components/
│   ├── ui/           # רכיבים כלליים: Button, Modal, ConfirmDialog, DataTable, Pagination...
│   ├── form/         # שדות טופס, FormField, useServerErrors, createFieldProps
│   ├── layout/       # AppLayout, Header, Sidebar, PageHeader, navItems
│   └── <נושא>/       # רכיבים של נושא אחד: students, groups, reports, secretaries, home...
├── context/          # AuthContext (המשתמשת המחוברת), ToastContext (הודעות)
├── routes/           # router, RequireAuth, RequireRole
├── pages/            # עמוד אחד לכל נתיב
├── lib/              # עזרים: עיצוב תאריכים וכסף, ולידציה משותפת, hooks קטנים
└── types/            # טיפוסים של התחום, מבוססים על schema.d.ts
```

### עקרונות שהקוד שומר עליהם
- **כל נושא בנוי באותה צורה:** `api.ts`, `hook.ts` ו־`schema.ts`. מי שמכירה נושא אחד, מוצאת את דרכה בכל נושא אחר.
- **קריאות לשרת רק דרך hooks.** עמוד לא קורא ל־Axios בעצמו. אחרי שינוי, ה־hook מרענן את הרשימות שהשינוי משפיע עליהן, דרך `queryKeys`.
- **שגיאות מטופלות במקום אחד:** שגיאות כלליות (אין חיבור, אין הרשאה, תקלה בשרת) מוצגות כהודעה קופצת אוטומטית. שגיאות של טופס (`400`, `409`) עוברות ל־`useServerErrors`, שמציג כל אחת ליד השדה שלה.
- **בלי שכפול קוד:** `npm run check` נכשל אם יש קוד כפול (jscpd). רכיבים חוזרים הוצאו לרכיב משותף, למשל `ReportsTable` שמשמש גם ברשימת הדוחות וגם בכרטיס התלמידה, ו־`NewPasswordFields` שמשמש גם בהחלפת סיסמה וגם בהוספת מזכירה.
- **בלי סודות בקוד:** כתובת השרת מגיעה ממשתנה סביבה. ה־Token נשמר ב־`localStorage`, ונמחק בהתנתקות.

## הרצה מקומית

**דרישות:** Node.js 22 ומעלה, והשרת `SwimSchool API` רץ במחשב (Visual Studio, פרופיל `http`, בכתובת `http://localhost:5136`).

```bash
npm install
npm run dev
```

האתר עולה בכתובת `http://localhost:5173`. בפיתוח לא צריך להגדיר כתובת שרת: Vite מעביר כל בקשה ל־`/api` אל השרת המקומי (`server.proxy` ב־`vite.config.ts`).

### פקודות
| פקודה | מה היא עושה |
|---|---|
| `npm run dev` | שרת פיתוח עם רענון אוטומטי |
| `npm run check` | בדיקת טיפוסים, oxlint ובדיקת שכפול קוד. חייבת לעבור לפני כל קומיט |
| `npm run build` | בנייה לייצור, לתיקייה `dist` |
| `npm run preview` | הרצה מקומית של הבנייה לייצור |
| `npm run gen:api` | יצירה מחדש של `schema.d.ts` מה־Swagger, כשהשרת רץ |

## העלאה לענן

האתר מתארח ב־Render כ־**Static Site**, ומתעדכן לבד בכל קומיט לענף `main`.

| הגדרה | ערך |
|---|---|
| Build Command | `npm install && npm run build` |
| Publish Directory | `dist` |
| `VITE_API_URL` | כתובת השרת בענן, בלי `/api` ובלי `/` בסוף |
| `NODE_VERSION` | `22` |
| Redirects/Rewrites | `/*` אל `/index.html`, מסוג Rewrite, כדי שרענון של עמוד פנימי יעבוד |

כתובת האתר צריכה להופיע גם בהגדרת ה־CORS של השרת (`Cors__AllowedOrigins__0`).
